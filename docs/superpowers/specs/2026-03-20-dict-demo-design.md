# 字典使用示例页设计

## 1. 背景

当前前端已经落地了一套通用字典基础设施，包含：

- 字典缓存与查询能力
- `DictSelect`
- `DictText`
- `DictTag`
- `CellDictText`
- `CellDictTag`

这些能力已经可以在业务页面中复用，但目前项目里还没有一个面向开发者的标准示例页，无法直观看到：

- 如何声明式接入字典下拉
- 如何在模板中渲染字典文本与标签
- 如何在 `vxe-table` 中声明字典列
- 默认 `detailCode` 与可选 `value` 匹配的差异

因此需要新增一个独立的示例页面，专门演示字典基础设施的使用方式。

## 2. 目标

新增一个独立的示例菜单与示例页面，路径为：

- 路由：`/examples/dict/basic`
- 页面：`playground/src/views/examples/dict/basic.vue`

该页面用于集中展示字典基础设施的典型使用场景，作为后续业务接入的参考模板。

## 3. 非目标

本次示例页不处理以下内容：

- 多页字典示例体系
- 动态切换字典编码的复杂交互
- 远程调试面板
- 字典维护页的二次改造
- 复杂业务字典联动演示

本次仅聚焦“标准接入示例页”。

## 4. 菜单与路由设计

### 4.1 放置位置

示例页放在现有 `Examples` 菜单体系下，新增独立字典示例节点。

建议结构：

- `Examples`
  - `Dict`
    - `Basic`

### 4.2 路由设计

建议在 `playground/src/router/routes/modules/examples.ts` 中新增：

- 父级节点：`/examples/dict`
- 子级节点：`/examples/dict/basic`

原因：

- 语义清晰，明确这是一组独立示例
- 后续如果增加更多字典示例，不需要重新调整整体路由结构
- 与现有 `form`、`vxe-table` 等示例分组风格一致

## 5. 页面结构设计

该示例页建议只做一个页面，不拆多个子页，页面内部按卡片分区展示。

### 5.1 页面整体结构

页面由以下四个区块组成：

1. 基础说明区
2. 下拉框示例区
3. 文本/标签渲染区
4. 表格示例区

页面目标不是追求复杂视觉效果，而是强调“怎么接入最标准”。

### 5.2 基础说明区

展示内容：

- 这套字典能力解决什么问题
- 默认按 `detailCode` 匹配
- 支持切换为 `value`
- 字典维护页保存后会刷新缓存

这一块用于给使用者建立正确认知，避免误用。

### 5.3 下拉框示例区

需要展示两个最典型的用法：

1. 默认匹配方式
   - `DictSelect`
   - 只传 `dictCode`
   - 实际绑定值为 `detailCode`

2. `value` 匹配方式
   - `DictSelect`
   - 传 `dictCode + matchField="value"`
   - 实际绑定值为字典项 `value`

每个示例旁边应显示当前选中值，方便使用者观察绑定结果。

### 5.4 文本与标签渲染区

需要展示：

- `DictText`
- `DictTag`

同样分别展示：

- 默认按 `detailCode` 渲染
- 按 `value` 渲染

这部分用于说明：不仅表单可以用字典，普通详情页、卡片区、描述区也可以直接接。

### 5.5 表格示例区

需要展示一个小型 `vxe-table` 示例表格，包含至少两列字典列：

- 一列使用 `CellDictText`
- 一列使用 `CellDictTag`

示例数据建议使用本地静态数组，不依赖真实业务接口，只依赖字典渲染能力本身。

这样可以把重点放在列配置方式上，而不是数据请求流程。

## 6. 示例数据设计

示例页中的业务数据建议使用静态本地数据，避免引入新的远程接口依赖。

例如可以使用字典编码：

- `enabled`

示例值分别覆盖：

- `detailCode` 模式：`enabled` / `disabled`
- `value` 模式：`1` / `0`

这样可以清晰展示两种匹配模式的差异。

## 7. 展示方式设计

### 7.1 风格要求

示例页应沿用现有 `examples` 页面风格：

- 使用 `Page`
- 使用 `Card`
- 信息密度中等
- 不做额外风格实验

### 7.2 文案要求

文案统一使用中文，说明要简短明确，重点突出：

- “默认按 detailCode 匹配”
- “按 value 匹配时需要显式声明”
- “表格列通过 CellDictText / CellDictTag 接入”

### 7.3 代码示意

如果页面已有合适展示方式，可以增加简短代码片段或配置说明；如果现有示例体系没有统一代码展示能力，则仅保留说明文案，不额外新增代码高亮组件。

本次优先保证页面易用，而非增加新的展示技术。

## 8. 技术设计

### 8.1 文件建议

建议新增：

- `playground/src/views/examples/dict/basic.vue`

如页面逻辑略多，可拆分：

- `playground/src/views/examples/dict/data.ts`

但如果页面规模可控，优先保持在一个文件中，避免过度拆分。

### 8.2 路由文件

修改：

- `playground/src/router/routes/modules/examples.ts`

### 8.3 国际化

如果 `examples` 菜单标题当前依赖多语言键值，则需要同步补充：

- `playground/src/locales/langs/zh-CN/...`
- `playground/src/locales/langs/en-US/...`

若当前 `examples` 菜单存在直接中文标题的惯例，则遵循现有项目风格。

## 9. 测试设计

至少应覆盖以下验证：

1. 路由与菜单注册
   - 新示例菜单可访问

2. 页面基本渲染
   - 页面可正常加载
   - 示例区块正常显示

3. 字典组件使用演示不报错
   - `DictSelect`
   - `DictText`
   - `DictTag`
   - `CellDictText`
   - `CellDictTag`

如果当前示例页测试体系较弱，则本次可先补最小 smoke test。

## 10. 风险与控制

### 10.1 风险

- 示例页如果同时承载太多功能，会变成“文档页”而不是“演示页”
- 如果直接复用真实业务接口，示例页稳定性会下降
- 如果示例页把字典能力讲得过重，会增加阅读负担

### 10.2 控制措施

- 控制在单页四个核心区块
- 用静态业务数据配合真实字典组件
- 只展示最标准的接入方式，不做高级玩法扩展

## 11. 结论

本次应新增一个独立的字典示例页，位于：

- `Examples -> Dict -> Basic`

通过一个单页示例集中演示：

- `DictSelect`
- `DictText`
- `DictTag`
- `CellDictText`
- `CellDictTag`

并明确展示默认 `detailCode` 匹配与 `value` 匹配的区别，使这套字典基础设施具备“可发现、可理解、可照抄”的开发者入口。
